# Friday mit Hermes-Standardfähigkeiten

Diese Übergaben beziehen sich auf die lokal gelesenen gebündelten `SKILL.md` von Hermes Agent v0.22.2 (2026-09-24). Ein sichtbarer Skill-Eintrag beweist nur Discovery. Vor einer Aufgabe muss Friday Werkzeug, Abhängigkeiten, Anmeldung, erlaubten Pfad und Ergebnis im aktiven Hermes-Prozess prüfen. `registry/integration_setup.json` bleibt ein statischer Einrichtungskatalog mit `live_status: unknown`.

## Direct coding from the Friday dashboard

Under **Skills → Coding mit Hermes**, the companion `rogue-friday` framework lets the owner select Codex, OpenCode or Claude Code, a Git repository and a task. Friday starts the selected native CLI through its bounded runner in Friday-Ubuntu, then shows run status/output and a stop control. Voice coding uses a configured project alias and requires speaker-verified confirmation after Friday reads back the task. This is a direct Friday feature; it does not use Hermes `terminal`/`process` or the Hermes CLI skills.

The dashboard checks that the selected skill is enabled, the native CLI can run in Friday-Ubuntu and Linux Git can access the repository. A launched process does not prove provider authentication, a successful model response or a code change. A fresh installer status check on 2026-10-16 reported native OpenCode 1.19.2, Codex 0.163.0 and Claude Code 2.1.301 as runnable in Friday-Ubuntu. Subscription authentication and a real coding task have not been verified. The older shell observation below records Windows shims and must not be read as a test of this newer runner.

## Beobachtung der lokalen Installation

Am 2026-10-16 wurden in `Friday-Ubuntu` Hermes v0.22.2 und die genannten sechs SKILL.md (PowerPoint, Computer Use, Obsidian, OpenCode, Codex, Claude Code) auf dem Dateisystem gesehen. `opencode` und `codex` lösten in dieser WSL-Shell auf Windows-Shims auf; `claude` und `soffice` lösten dort nicht auf. Das ist kein Auth-, Tool- oder Ausführungsnachweis. Telefonie wurde weder als gebündelter Skill noch als Friday-Dial-Adapter gefunden. Die separate laufende Friday-Installation lieferte bei einem autorisierten Katalogabruf 158 sichtbare Skills (105 Friday, 53 Hermes), ohne Katalogfehler; einzelne Skills und externe Anbieter wurden dadurch nicht ausgeführt.

Eine gezielte Laufzeitprobe am 2026-10-16 mit dem installierten Hermes-`powerpoint`-Skill v1.1.0 und synthetischen Daten bestand: `pptx_create.py` erzeugte zwei Folien, `pptx_read.py --outline` las Inhalt und Notiz zurück, `pptx_render.py` erzeugte mit dem installierten LibreOffice/Poppler zwei visuell geprüfte PNGs. Die PPTX-Dateistruktur und CRC waren gültig. Geprüft wurde der vom Installer bereitgestellte Friday-Python-Launcher mit `python-pptx` 1.0.2; `/usr/bin/python3` allein hat diese Bibliothek nicht. Das belegt weder Hermes-Modellrouting noch Windows-Office-Animationen oder die Bearbeitung privater Markenvorlagen.

Die jeweilige Hermes-Skilldatei ist der versionsgenaue Vertrag für konkrete Skriptargumente und Toolaktionen. Nach einem Hermes-Update diese Übergaben erneut gegen den installierten Stand prüfen.
