# Web extraction adapter

`adapters/web_extraction.py` implements bounded extraction of one HTML response for F.R.I.D.A.Y. research. It is offline by default and returns provenance fields for citation review: `injected-transport`, `scrapling-static`, or `scrapling-stealth`. Both optional Scrapling transports run only after a trusted host capability grants the exact URL, time, and byte limits. Synthetic tests cover CSS fields, tables, markdown, challenge/empty pages, access denial, rate limits, redirects, node/depth/byte bounds, untrusted prompt-like page text, and fake static/browser fetchers. Tests make no outbound requests.

The host transport is the network security boundary. It must bind DNS results to approved public IPs and enforce exact host policy on the initial request, redirects, and every browser subrequest, with an aggregate ingress-byte cap during transfer. The adapter checks the returned body only after receipt. Browser `page_setup` installs a Playwright request route before navigation, blocks service workers, and aborts URLs outside the exact HTTPS host or methods other than GET/HEAD; that route is defense in depth, not a complete SSRF or download-size control. Scrapling may swallow `page_setup` exceptions, so the adapter rejects a result if route installation was not observed. Browser retries are one attempt, wait is zero, and Google referrer and Cloudflare solving are disabled. There is no automatic escalation from static fetch on 403/CAPTCHA. See the [skill extraction reference](../skills/research/friday-web-research/references/EXTRACTION.md) for a usage example and limits. Live operation requires a host implementation of the network boundary; no live target was exercised in the tests. Crawl4AI and Firecrawl remain unintegrated.
